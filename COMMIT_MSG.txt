refactor: organise the repo, and add config.json to switch features off

The repo root had 24 test files sitting next to package.json and the README,
which made the project look like a pile of loose scripts rather than a program.
The tests now live in tests/ with a runner, and the developer tools in
scripts/.

config.json is the new way to turn things off. It is committed on purpose, so
the settings travel with the code, and it holds no secrets - those stay in
.env. A command that is off is not registered with Discord at all, so it leaves
everyone's palette, and typed commands stop parsing. The loader is forgiving:
a missing file, a broken file or a value of the wrong type all end with the
bot running on the defaults rather than not starting.

Also adds start.sh, because a long startup command pasted into a web form gets
truncated, and a truncated one fails quietly - the cut part is usually the
npm install, so the bot dies with a missing-package error that looks nothing
like the cause. The start command is now 29 characters.
